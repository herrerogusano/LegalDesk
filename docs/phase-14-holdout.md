# Phase 14 — semantic holdout runner

`evals/phase14_holdout_runner.py` is the local runner for the frozen
`evals/phase13_holdout.json` contract. It is deliberately separate from the
application runtime and from the Phase 12 lexical/debug runners.

## Preflight (zero AWS/network calls)

Preflight verifies the fixture byte hash and exact case order, the general and
stage prompt hashes, the resolver/writer contracts, the exact model IDs
supplied by the operator, the release Git SHA, and the release artifact
SHA-256. A model ID may itself be an approved Bedrock inference-profile ARN;
there is no separate profile argument because the model ID passed to each
Converse stage is the identifier that controls that call. It also verifies the
fixed call ceiling and report path.

```powershell
python -m evals.phase14_holdout_runner preflight `
  --resolver-model-id eu.anthropic.claude-sonnet-4-6 `
  --writer-model-id eu.anthropic.claude-sonnet-4-6 `
  --release-commit <release-git-sha> `
  --artifact-sha256 <release-artifact-sha256> `
  --output evals/results/phase14-holdout-<unique-run>.json
```

The preflight command does not import `boto3` and does not make an AWS or
network request. A changed fixture, prompt, contract, or release identity
stops the run before a provider client can be created.

Preflight also runs two local negative canaries. The fixture's
`candidateCitationIds` for `invented-citation` are submitted only to the
server-side citation validator and must be rejected; the fixture's negative
role-reversal answer is submitted only to the bounded grounding adapter and
must be rejected. Reports retain only the codes
`CANARY_INVENTED_CITATION_REJECTED` and `CANARY_ROLE_REVERSAL_REJECTED`.
These checks are separate from scoring a correct provider output.

## Bounded provider execution

Execution requires the same explicit metadata plus a second `--execute`
acknowledgement. The runner creates a Bedrock Converse client only after the
preflight gates pass. The client is configured with one SDK attempt and the
runner has no retry path.

The hard ceiling is **14 resolver calls + up to 13 writer calls = 27 model
calls**. The `unrelated-evidence` case legitimately skips the writer only
when the resolver returns the canonical no-evidence status. Any other
unexpected `none` result is scored as a resolution mismatch and never triggers
an extra call. The runner compares the exact expected `coverage` and `conflict`
combination as well as the derived public evidence status, so `partial` cannot
silently pass as `none`. Resolver output is validated against server-owned citation IDs;
invented IDs fail closed. Writer grounding is checked by the existing bounded
fixture oracle plus narrow holdout-specific adapters for partial evidence and
role/injection safety.

The model receives only the question and synthetic passages whose citation IDs
were generated by the runner. `candidateAnswer`, `candidateVerdict`, and
`candidateCitationIds` are oracle-side expectations/canary inputs only: they
are never part of a provider request and never appear in a report. Grounding
specs declare their accepted lexical variants explicitly; candidate answers
are not used to widen the oracle.

```powershell
python -m evals.phase14_holdout_runner execute --execute `
  --resolver-model-id <approved-resolver-model-or-profile> `
  --writer-model-id <approved-writer-model-or-profile> `
  --release-commit <release-git-sha> `
  --artifact-sha256 <release-artifact-sha256> `
  --output evals/results/phase14-holdout-<unique-run>.json
```

Reports are metadata-only and create-only. They contain case IDs, status
labels, citation counts/IDs, bounded validation/error codes, model/prompt
provenance, call counters, and the release hashes. They do not contain
questions, passages, answers, prompts, tokens, secrets, or chain-of-thought.
An existing report path is rejected; no report is overwritten.

The maximum provider cost is an estimate derived from the approved model's
regional input/output rates and actual metered tokens, not a billing cap. The
27-call ceiling, bounded `maxTokens` (256 resolver / 512 writer), zero
temperature, and zero retries are the enforceable local limits. Confirm the
numeric cost envelope in `docs/phase-14-cost-operations.md` before any real
execution; this repository change itself performs no inference.

## Independent review attestation

Attestation is a separate create-only command. It pins the exact report SHA,
requires a reviewer identity, a decision, and at least one reason code. The
known runner identity is rejected as reviewer, so the runner cannot
self-approve its own evidence. This is procedural separation only: a reviewer
ID and report hash cannot cryptographically prove that a human is independent
or that the review was performed without collusion; operational identity and
approval controls remain part of the release gate.

An `approved` attestation is fail-closed: the report must contain all 14 case
records accepted, zero retries, no more than 27 inference calls, a passing
preflight, and both successful local safety-canary codes. Failed or incomplete
reports may receive `rejected` or `needs_follow_up`, but cannot receive
`approved`.

```powershell
python -m evals.phase14_holdout_runner attest `
  --report evals/results/phase14-holdout-<unique-run>.json `
  --reviewer-id <independent-reviewer-id> `
  --decision approved `
  --reason-code all_cases_grounded `
  --output evals/results/phase14-holdout-attestation-<unique-run>.json
```

The holdout has not been executed against AWS by this local implementation.
Until a real report and an independent attestation exist, the Phase 14
semantic-release gate remains pending.
